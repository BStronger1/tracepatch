# 失败归类与证据边界

先分清最终验收、提交和源码变化，再人工分析具体实现。
工具不从“重复命令”“长时间阅读”或模型自述推断思考停滞、遗忘和根因。

## 可自动归类的记录

| 类别 | 所需记录 | 不应推断 |
| --- | --- | --- |
| verified_submitted | 独立验收通过且底座记录 Submitted | 所有上游行为都正确 |
| verified_without_submission | 验收通过，底座没有 Submitted | 修复一定错误 |
| submitted_but_acceptance_failed | Submitted 但独立验收失败 | 提交就是成功 |
| acceptance_failed_after_observed_edits | 验收失败且记录过源码修改 | 修改必然无价值，或知道失败原因 |
| acceptance_failed_without_observed_edits | 验收失败，观测完整且从未记录修改 | 没有思考进展 |
| acceptance_failed_edits_unknown | 验收失败，修改记录缺失或不完整 | 没修改 |
| acceptance_unknown | 缺独立验收、异常退出码或基础设施错误 | 验收失败或通过 |

撤回过的修改仍算“记录过修改”，另报最终相对初始源码是否有净变化。
阶段、公开检查和自写检查分别记录，不合成一个效果分数。
只有最终观测源码版本匹配的检查才能被用于描述当前状态；旧版本成功不能覆盖新版失败。
自写检查若修改源码，其进程成功不作为最终版本的检查通过。

可附加的观察包括：当前公开复现通过但独立验收失败、自写检查通过但验收失败、
Python 工具调用数及测试期间修改源码的次数。它们不证明测试为何漏检。
历史运行缺少工具记录时返回 null；不能将工具未提供写成模型拒绝使用。

## 已有人工复核案例

| 现象 | 证据与解释 |
| --- | --- |
| 没有形成源码修改 | [Click 新工具组](../reports/forward-tool-study-001.md)的替换脚本匹配失败，24 个动作均为 bash；仅“提供工具”没有保证采用。 |
| 修改后违反兼容性要求 | [公开检查实验](../reports/public-checks-study-001.md)中公开复现通过，独立验收为 9/10；子类构造或配置状态处理不正确。 |
| 自写断言有错 | [签名与约束实验](../reports/symbols-study-001.md)将 '/q' 与 'q' 混淆；用参考版和候选版核实，不能把自测失败直接归因于候选实现。 |
| 原验收覆盖不足 | [Click 事后审计](../reports/forward-tool-study-001.md)在通过十组验收并提交后，仍发现上下文泄漏和参数绑定冲突。原分数保留。 |
| 工具执行成功但并未测试 | [阶段实验](../reports/stages-study-001.md)的 Python 工具一次改写源码后退出零，源码版本检查使其不被当成最终版本通过。 |
| 输出或提交协议失败 | [输出额度实验](../reports/output-budget-study-001.md)分别统计截断、冻结验收和提交；更多输出预算不等于更正确的补丁。 |

以上是不同实验条件下的个案，不合并为“某策略修复率”，也不把同时出现的现象称为已证实的因果链。

## 离线使用

```powershell
python scripts/audit-failures.py --run runs/<batch>/<batch>--<task> --output artifacts/triage-new.json
```

可重复传入 `--run` 比较多个运行；重复目录会被拒绝，输出文件须不存在。
该命令只读取选定的 JSON 记录，不执行轨迹、补丁或测试代码，不调用 API，不启动 Docker。
输出保留来源文件 SHA-256，省略原始命令、测试代码及日志正文。
这些哈希用于追溯本地记录，并非签名、原始日志真实性证明或重新执行验收。
自动归类依据记录中的独立验收状态；它不会发现冻结测试尚未覆盖的缺陷。
