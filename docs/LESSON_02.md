# 第二课：真实 Agent 修复与独立验证

这是一道自建教学任务，不是 SWE-bench 或 Terminal-Bench 结果。它验证软件链路，不验证泛化能力。

## 分工

- 上游 mini-swe-agent DefaultAgent 控制模型调用和工具执行循环。
- 本项目 DmxModel 是薄接口适配器，提供 DMXAPI 调用、格式解析、用量记录和固定请求限制。
- 上游 DockerEnvironment 执行命令；Windows 子类仅修复容器清理命令的跨平台兼容性。
- 外部验证器在 Agent 退出后的新容器中运行。只带入 ranges.py，不沿用 Agent 修改的测试和环境。

## 查阅顺序

1. tasks/smoke/workspace/ranges.py：原始缺陷。
2. runs/smoke-003/before.json：确认原始代码确实失败。
3. runs/smoke-003/trajectory.json：逐轮读取 assistant 动作与随后 user 观察。
4. runs/smoke-003/patch.diff：查看模型实际修改。
5. runs/smoke-003/result.json：独立验证结果、用量估算与固定版本。

本次三轮均保留：001 请求超时且费用未知；002 三次格式错误，验证失败；003 关闭思考并兼容完整 bash tool_call 文本，前两次格式错误后继续执行，最终 6 个外部用例通过。没有把调试过程视为独立测试集或统计成功率。

只有运行成功才会产生完整结果文件。requests.json 在网络请求前记录尝试，失败也保留，不自动重试。

## 预算与限制

单次请求输入 JSON 不超过 24,000 字节。001 输出请求上限 1,024 Token，002/003 为 512 Token 并显式关闭思考，总计每轮最多 8 次模型请求。
按用户报价以每次 0.1 元预留，共不超过 0.8 元，连同探测预留 1 元。实际费用以供应商账单为准；若供应商未遵守输出限制则停止。
本脚本固定单次运行目录，拒绝覆盖或自动重复收费。还未实现通用多实验账本，下一阶段扩展时必须先补齐。
