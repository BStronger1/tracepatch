# 阶段路线

按当前工作安排先完成工程与实验，再逐步讲解；正式投递时只使用已完成且本人能解释的内容。

| 阶段 | 工作 | 验收条件 |
|---|---|---|
| 0 环境与读轨迹 | 固定源码版本、Docker 检查、离线诊断 | 合成样例可运行，理解动作与观察的区别 |
| 1 真实基线 | 配置 API，容器内完成一个代码修复任务 | 真实轨迹、补丁、外部测试、实际用量齐全 |
| 2 失败归因 | 独立开发任务，人工阅读失败轨迹 | 错误分类、证据位置、优先解决的问题 |
| 3 单项改进 | 优先实现证据保存与上下文回读；必要时加入恢复 | 模块测试、成功与反例、可关闭的策略开关 |
| 4 受控实验 | 原版/单项/组合；Harbor 集成 | 固定任务、模型、预算，独立测试与成本报告 |
| 5 GitHub 发布 | 文档、示例、CI、贡献说明 | 新用户能独立运行；发布前确认名称、许可证、公开材料 |
| 6 简历与面试 | 基于真实证据写项目条目 | 每个数字可追溯，每项贡献能解释并现场演示 |

硬件策略：本机开发，API 推理，Docker 单并发起步。先测单任务资源与费用，再决定规模。不开启未经定价确认的付费批量运行。
