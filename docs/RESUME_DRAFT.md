# 简历素材草稿：仅覆盖已实现内容

**TracePatch：Coding Agent 执行诊断与失败恢复实验工具**

- 基于 mini-swe-agent 构建本地 Docker 执行与独立验证流程，接入模型 API，记录执行轨迹、补丁、任务哈希与运行快照。
- 实现动作格式诊断、输出截断识别及定向恢复反馈；实现带进程锁、原子写入和未知费用保留的请求预算账本。
- 建立 3 个开发任务并完成同配置双组实验，分别报告补丁正确性、正常提交、调用与报价估算；另实现完整工具输出留存与有界预览模块，尚未验证其模型效果。
- 扩展三文件任务队列修复与清单式源码导出，设计 8 组业务契约测试，通过逐模块回归注入验证测试有效性；实测恢复组补丁通过，但未在步数上限内正常提交。
- 接入 Requests 历史真实 issue：冻结源码与镜像，隔离参考修复与独立回归，导出允许的源码并验证；从真实轨迹复现输入超限，实现保留任务和最近完整交互的有界上下文选择。修复效果按公开报告表述，不写标准基准分数。
- 实现原生函数工具调用、严格参数校验和调用—结果配对；在同一 Requests 历史 issue 的两次干净复测中均完成提交并通过 5 组独立回归，分别使用 21/22 次模型调用，动作格式拒绝均为 0。此为单题重复结果，不表述为跨任务 100% 成功率。

新增进展：接入 3 个不同的 Requests 历史问题；两道新题运行前冻结各 6 组回归。重定向候选通过冻结测试但未提交，事后诊断发现新增参数冲突；Cookie 候选多次输出截断且补丁为空。详见 reports/new-requests-study-001.md，不能写成三题修复成功。

## 精简投递素材（需能亲自解释后使用）

**TracePatch｜Coding Agent 上下文管理与失败诊断｜Python、Docker、LLM API**

GitHub：https://github.com/BStronger1/tracepatch

- 基于 mini-swe-agent 构建本地执行与独立验证工具，接入原生函数调用、严格参数校验及预算账本，留存轨迹、补丁、任务哈希和运行快照。
- 实现有界上下文选择、逐动作源码指纹与版本化证据记忆；静态提取函数签名并引用原任务约束，历史删减时补回证据，代码变化后使旧卡片过期。
- 建立 Requests、Click 两个仓库共 6 个历史问题的可复现评估及多文件开发任务，适配不同源码布局并隔离独立测试；通过回归和补丁审计发现“测试通过但仍有新增缺陷”的案例，公开成功与失败结果。项目 92 项本地离线测试通过。
- 实现公开复现脚本冻结、源码版本绑定和新容器检查，将公开检查、自写测试与独立验收分开；对异常保留未知状态，并提供可审计的证据反馈，不自动代替 Agent 提交。
- 新增结构化 Python 测试工具，监督进程直接采集退出状态并处理超时；绑定测试代码和源码版本，截断长输出时保留完整状态和合法 JSON，避免外层 shell 覆盖这一路径的测试退出码。
- 实现可关闭的阶段调度，根据源码版本、检查记录及剩余调用安排检查节点；通过原生工具选择约束和适配器校验要求结构化测试，区分自主采用与调度器干预，保留源码修改及提交的模型决策。
- 开发离线结果归类工具，按验收、提交和源码变化区分失败状态，识别当前版本的公开检查与独立验收差异；在 16 次保存的运行中生成带来源哈希的审计报告，不重放轨迹、不将观察标签写成因果结论。
- 实现版本化离线重评，校验源码来源并保留历史成绩；将 Cookie 回归扩展至 10 组，定位并修正收尾提示与提交协议不一致的问题，通过 5 种 Docker 提交情形验证。
