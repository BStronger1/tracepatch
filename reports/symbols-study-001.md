# 完整函数签名与原任务约束：首次冻结对照

2026-09-26。在同一 Requests Cookie v2 开发题上比较普通片段和结构化证据。
**结构化组通过十组预先冻结的独立回归，普通片段组未通过；两组均未正常提交。**
这是各一次的开发案例，不支持稳定提升或单项机制的因果结论。

## 依据与实现

[上一轮卡片审计](memory-coverage-audit-001.json)检查实际注入的 16 张不同且版本匹配的源码卡片：
10 张缺少包围片段起点的函数完整签名，4 张包含签名，2 张起点位于函数之外。
审计根据哈希匹配已有基础或最终源码，不补造中间状态，也不把缺签名直接认定为修复失败原因。

新增[静态作用域提取与任务提示](../docs/STRUCTURED_EVIDENCE.md)：
用 AST 定位函数，返回标准化完整签名、参数名、限定名称和所属类；不导入源码或执行默认值。
语法失败、签名过长明确标记；旧签名随源码版本失效。
任务提示逐字来自原有任务，附字符位置和哈希，不读取隐藏验证条件。
原任务本来就保留，此处只是突出原文约束。

64 项本地离线测试通过。[Docker 集成检查](symbols-docker-check-001.json)确认：
从函数体片段可取得完整多行签名，原文约束可以核对，版本变化后不补回旧签名。

## 对照条件

[冻结计划](symbols-plan-001.json)在首次调用前保存实现、配置与任务哈希，
[机器报告](symbols-study-001.json)核对唯一计划差异为 `memory_profile`。
两组均启用记忆、关闭进展提醒、使用同一采集器；源码卡片均含 AST 数据，只改变召回表达。

共同条件为 qwen3.8-flash、recovery-submit、原生工具、最近完整历史、公开最小复现、
1024 输出 Token、24 次调用上限、24000 字节请求上限、4200 字节卡片上限，以及同一源码和 Python 3.9 镜像。
错误版和参考版的预检查均通过预期判定。参考修复与独立验证器不提供给 Agent。
顺序为 excerpts → structured，各一次，没有重跑、调参或变更验证器。

结构化方案同时改变签名呈现和任务约束提示，不能拆分归因为“仅 AST”或“仅约束”的效果。
它也会改变有限输入中的内容分配，不是额外增加上下文额度。

## 结果与注入证据

| 指标 | 普通片段 excerpts | 结构化 structured |
| --- | ---: | ---: |
| 十组独立回归全部通过 | 否，2 次错误 | 是 |
| 正常提交 | 否 | 否 |
| 调用 / 执行动作 | 24 / 24 | 24 / 24 |
| 首次源码修改动作 | 11 | 17 |
| 记忆补回请求 | 13 | 15 |
| 显式 AST 签名出现次数 | 0 | 30 |
| 原任务约束卡片出现次数 | 0 | 15 |
| 历史删减请求 | 13 | 15 |
| 截断拒绝 / 采集错误 | 0 / 0 | 0 / 0 |
| 运行耗时（秒） | 165.250 | 102.047 |
| 报价估算（元） | 0.103933230 | 0.097411860 |

30 次签名出现对应 8 个不同函数，多次重复补回，不是 30 个独立函数。
其中既有 Cookie 更新函数，也有 MockRequest 和请求 hook 函数；数量不能代替相关性或完整覆盖评价。
普通片段也可能恰好含签名；表格的零仅表示没有显式 AST 字段。
每次原任务卡片含六段可逐字核对的原文，所有请求未超过 24000 字节，没有卡片预算回退。
过期和未知版本均不补回旧源码或旧签名。

## 两种失败必须区分

普通片段组修改 `RequestsCookieJar.update`，调用并未定义的 `_put_copy` 方法，独立验证报 AttributeError。

结构化组的最终补丁通过十组独立回归，但最后仍在修复自写测试。
轨迹中，它创建 Cookie 时传入 `path='/q'`，随后却断言复制后的路径为 `'q'`。
[事后离线诊断](symbols-path-audit-001.json)在参考版和候选版分别检查，均正确保留 `'/q'`，
因此该断言与输入矛盾。此诊断未修改补丁、冻结验证器或原成绩，也没有模型调用。
它只核实这个路径问题，不代表整份 Agent 自写测试都已审查正确。

最后一条动作的自写测试失败，未打印提交标记，之后达到调用上限。
该命令还以 grep 输出开头，并让后续日志命令掩盖了测试的非零退出；
工具返回零不能代表测试通过，打印提交标记之前有输出也不满足现有提交协议。
补丁验证和正常提交保持分开记录，没有由 Harness 代替模型提交。

## 可支持的结论

已实现并验证完整签名提取、原任务约束引用、版本失效及受控切换；
本次结构化条件有一个独立回归通过的案例。不能写“成功率提升 100%”“显著加速”或可靠跨仓库修复。
每组一次、已知开发题、两项信息一起改变，缺少独立保留集和重复验证。

候选还修改了 `structures.py`、`utils.py` 中的 collections 相关兼容代码，
本轮只验证固定 Python 3.9 环境和自定义回归，没有覆盖全部上游测试或其它 Python 版本。
历史公开修复也可能进入模型训练数据。当前仍是两个仓库、四个不同历史问题。

下一步应先明确区分公开复现、独立验证和 Agent 自写测试的来源，
定位错误自测与收尾流程，避免继续用新增记忆机制掩盖执行问题。

48 次调用按既有报价估算合计 **0.20134509 元**，无未知费用请求；不是提供商账单。
沿用继续实验授权将保守预留上限提高到 70 元，累计预留 60.2 元、剩余 9.8 元，历史记录保留。
